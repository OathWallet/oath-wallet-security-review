# Evidence rules

Never change a review status merely because tests or scanners pass. A reviewed
disposition needs a source hash, explicit scope and evidence. Preserve failed
attempts, skips, findings and limitations. Do not claim independence, zero bugs,
superiority over other wallets or App Store equivalence without separate evidence.

Use only public application source and synthetic fixtures. No real credentials,
funded transactions, production-provider secrets, App Store jobs or physical devices.
Default to host tests and generic iOS compilation. Runtime checks require a stated
unresolved concern. Do not enable optional live tests in inherited environments.

Pin source revisions and third-party actions. Do not use pull_request_target,
write tokens, repository secrets or self-hosted runners to execute PR code.
Never alter historical evidence; append a superseding result.
