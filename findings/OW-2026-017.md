# OW-2026-017 — Session expiry unit mismatch and unchecked timestamp conversions

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

Severity: **low**, dependency API availability and state correctness. No remote
Oath exploit, unauthorized signature, secret exposure or financial loss was
established. The reachable-call-path limitations below are part of this rating.

## Affected source and reproduction

Regression-only baseline: `43281bdf88781f28f12cddbf87ec9dee03079e8b`.

- [WCSession.swift, lines 166–184](https://github.com/devdasx/oath-wallet/blob/43281bdf88781f28f12cddbf87ec9dee03079e8b/Vendor/Reown/Sources/WalletConnectSign/Types/Session/WCSession.swift#L166): the absolute extension check compared new milliseconds against old seconds. A shorter or already-past expiry could pass. The conversion to unsigned milliseconds trapped for `Int64.min` and `Int64.max`. A negative relative TTL could also update an already-expired session to another past time.
- [Request.swift, lines 69–81](https://github.com/devdasx/oath-wallet/blob/43281bdf88781f28f12cddbf87ec9dee03079e8b/Vendor/Reown/Sources/WalletConnectSign/Request.swift#L69): decoded or mutated expiry values bypassed the initializer's TTL bound. `UInt64.max` trapped on conversion to `Int`; an eight-day request was accepted.

The [WalletConnect RPC contract](https://specs.walletconnect.com/2.0/specs/clients/sign/rpc-methods)
uses seconds for absolute session expiry and bounds specified request expiry at
seven days. This repair does not claim to prove the entire SDK's compliance.
The existing missing-expiry relay default and elapsed requests' remaining TTL
are preserved, rather than treating a remaining TTL below five minutes as a
new invalid request.

## Repair

Implementation: `fd002d9272a767352c114e8b752a21f65f0694cc`.
[PR 25](https://github.com/devdasx/oath-wallet/pull/25) merged as
`e7098290f50451a071f2a27c08e5bdde336ea4b1`, with the identical tested source tree.

- Relative extension TTL must be positive and at most seven days before date construction.
- Absolute extension must remain in the future, not shorten the current whole-second expiry, and remain within seven days. It no longer converts to unsigned milliseconds.
- The whole-second comparison preserves idempotent acknowledgements of extensions originally stored with subsecond precision.
- Request TTL must be finite and at most seven days before conversion to `Int`.
- Invalid extensions throw without changing the stored expiry.

No stored wallet identity, signing operation, schema or migration changed.
Source publication does not imply availability in the App Store.

## Reachability and remaining gaps

`SessionExtendRequestSubscriber` first requires `session.peerIsController`.
`ApproveEngine.createSettleParams/createSession` makes the wallet the controller
for ordinary Oath-approved sessions, so a dapp's extension is rejected before
the affected function in that path. The response subscriber applies the locally
stored outgoing request's expiry. These guards limit the demonstrated impact.

`Request.calculateTtl` is called by outgoing relay/link request implementations.
The reviewed Oath service acts as wallet responder; this review did not identify
an Oath call sending such a request or demonstrate an inbound route to that trap.
Other integrations or persisted/migrated sessions were not exhaustively tested.

Namespace validation, request-dispatch TTL propagation, link redirect assumptions,
other date-helper callers, timer lifetimes and the remaining SDK are still under
review. They are not declared fixed by this change. No simulator, physical
device, live relay, blockchain transaction or App Store operation was performed.
