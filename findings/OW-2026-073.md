# OW-2026-073 — Solana token delegation omitted from signing consent

Severity: **Medium, misleading transaction authorization.**
Status: **Fixed in public source and locally retested.**

Reported by **Ibnu** against Oath Wallet 5.0.2 (104), commit
`7ffd0f449c3312d9fafd01eda59c6b9eb813f9ca`. This checkpoint independently
reproduces the review-model omission using synthetic account responses. It does
not claim to reproduce the reporter's separate local-validator experiment.

The old `WalletConnectSolanaClient.swift` constructs a review from fees, program
identifiers, balance differences and a slot. SPL Token delegation changes do not
necessarily change balances. A transaction that authorizes another key to spend
tokens could therefore appear as a fee-only operation. Different delegates could
produce identical review values. The UI had no delegation details to display.
An unlimited allowance can enable later token transfers by that delegate; the
initial transaction still requires the user to approve and sign. No signature
bypass or unauthorized signing without user approval is demonstrated.

Public repair [`7c79fe5`](https://github.com/OathWallet/oath-wallet/commit/7c79fe5bf89de44168fc9bc25e7e781d9051fdfe)
adds per-token-account before/requested/after delegations, exact spender and
allowance display, an unlimited-allowance warning, and consent comparison that
includes permissions. It handles both token programs, direct Approve and
ApproveChecked, and delegation changes visible in simulated account state.
Unsupported account-control changes are rejected. Oversized writable-account
sets fail rather than yielding a partial preview. This repair was already
published before this audit checkpoint; no new application change or PR is
claimed here.

The identical regression runs against the reported source and repaired public
commit `247ac898168cc8f97be28398c69337f569fb5f96` (5.0.3 / 105):

- Before: exactly one expected assertion failure: a different delegate produced
  an identical review. The baseline compiled successfully.
- After: that assertion passes; all **36 selected Solana host tests pass**,
  with zero failures and zero skips, using a separate fresh build.
- Test execution denies network access. Fixtures use disposable, deterministic
  synthetic keys and injected RPC responses, not funded accounts.

[Reproduction, evidence, source ranges and remaining limitations](../review/SOLANA-CONSENT.md).
The tested repair's presence in a later source release does not establish its
availability in Apple's distributed application. The whole-wallet review is
still incomplete and is not independent certification.
