# OW-2026-065 — NEAR transaction reader traps on nonzero-origin Data

Status: **Fixed in public source and locally retested; hosted replay pending.**

Severity: **Low, library availability.** Passing a valid `Data` slice to the
public `WalletConnectNearTransaction` initializer terminates the process with
SIGTRAP. Current request decoding constructs fresh zero-origin data; this review
has not demonstrated a remote application path, unauthorized signing or fund loss.

## Reproduction and cause

At `0614556b993f85808b13e3a69984ce36050a8dfe`, the reader in
`Packages/OathAnkr/Sources/OathAnkr/WalletConnectNear.swift:126` uses a logical
byte offset directly as a collection index. Swift Data slices can preserve a
nonzero `startIndex`. The remaining-byte guard passes, then the subscript traps.

The audit creates a valid transaction with pinned near-api-js 7.3.1, prefixes
one byte and passes `dropFirst()` to the production initializer. Four control
methods pass; the slice method exits with signal 5 before any assertion result.
The sanitized crash stack identifies `Data._Representation.subscript.getter`,
`NearConnectReader.take`, and the transaction initializer. The original process
log and exit status are retained, not converted into a successful test.

## Repair and regression

Commit `5d91d1e4dfd36c56031c7a8fb1ee305446dc54de` derives each range from
`bytes.startIndex`, preserving the existing length checks. It changes no wire
format, account identity, signing authorization or persistence format.

The exact five-method audit fixture passes after repair. A separate 26-method
production-package replay passes, including new tests for valid slices with
prefixes of 1, 7 and 64 bytes, truncated slices and trailing data. Independent
Node crypto verification accepts all 82 production-generated signatures, and
encoded transactions match the pinned SDK bytes. Test networking is denied.
