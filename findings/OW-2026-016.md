# OW-2026-016 — SDK event opt-out did not cover the full lifecycle

Severity: **low**, privacy/minimization and event-state correctness. No private
key, recovery phrase, unauthorized signature or financial loss was demonstrated.

## Affected behavior and source

The original Events client at `e7aed8c9d08357df10a4f85be7d069a66fad07f8`
queued an initialization event even when disabled. Message events also lacked an
enabled-state guard. Disabling only cleared stored error events; message/init
queues and the current trace remained. The default persistent flag was true.
Oath disabled telemetry after configuring its SDK clients, leaving construction
and any previously scheduled worker ahead of that policy application.

`EventsClient.sendStoredEvents` checked the flag once, then awaited a dispatcher
that delayed/retried independently. It retained no cancellable task handle and
its acknowledgement cleared whole queues without checking generation or whether
new events had arrived. `NetworkingService` wrapped a callback data task without
propagating Swift task cancellation.

The event types contain SDK/client identifiers, bundle/user-agent information,
request correlation identifiers and error traces. These are not wallet secrets.
A synthetic transport proves a request can retry after disable; this review did
not capture a real user's events or demonstrate historical production delivery.

## Repair and publication

Implementation: `4cfeb14ce9bd85ca2d10017cb053ab421df30cf2`.
[PR 24](https://github.com/devdasx/oath-wallet/pull/24) is merged as
`fcacff8cdf24c369ea79c6aba26f58e6252bd8cb`, with the same tested source tree.

- The Oath factory sets the disabled policy before client construction, including
  when a legacy stored setting is true. Fresh SDK state also defaults to false.
- All collection paths check the policy. Opt-out purges error, message and init
  queues and clears the in-memory trace/topic.
- A lock serializes policy/queue access. One task owns delivery; disable cancels
  it and invalidates its generation. Dispatcher checks cancellation/authorization
  before attempts and after delays/failures.
- An acknowledgement applies only to its generation and unchanged queue revision.
  Events added during delivery survive. If the queue changes, the old batch may
  be delivered again after a future explicit enable; it is not silently erased.
- The HTTP service uses cancellation-aware URLSession async delivery. A request
  already received by a server cannot be recalled.

No wallet identity, signing, encrypted peer relay message or wallet-storage
migration changed. Source availability is not App Store availability.
