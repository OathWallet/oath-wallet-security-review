# OW-2026-062 — Wallet removal ignores pending dApp submission journals

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

Severity: **Low, recovery and retention correctness.** No unauthorized signature,
key exposure or loss of funds was demonstrated.

## Affected source and trigger

At baseline `c7acd23bb139864a40273f405d18b479589d2b20`,
`Packages/OathDatabase/Sources/OathDatabase/WalletLifecycle.swift:23–31`
(`validateWalletRemoval`) and
`Packages/OathDatabase/Sources/OathDatabase/OathDatabase.swift:210–241`
(`deleteWalletMetadata`) check only ordinary `sends`. The same two function
bodies remain unchanged at reproduction commit
`31178e42e40d67218c2b52eda0024a5b4224f376`.

Seven WalletConnect submission tables retain separate pending signed work.
Removal preflight accepts a wallet with those rows; metadata purge cascades
them. Soft removal also hides pending recovery queries because they require
an active wallet. Affected journals cover Bitcoin, Solana, Sui, TON, NEAR,
Stellar and XRP. This finding is about preserving pending recovery work,
not a claim of seven-chain transaction execution or proven lost funds.

The app calls removal validation in
`OathAtmosphere/Wallet/OathWalletVault.swift:2336–2369`. Unlock reconciliation
purges expired removed records around lines 2245–2275; Connect recovery reads
pending rows in `OathAtmosphere/Scanner/OathWalletConnectService.swift:2278–2337`.
These are limited call-path traces, not a full review of those large files.

## Reproduction and repair

Four production-database methods initially yield two passes and two failures,
with **46 failed assertions**. A signed synthetic XRP transaction is reopened
from disk, and removal/purge incorrectly accept its signed, unknown and accepted
states. A separate schema-only matrix covers 20 table/state combinations and
both removal operations, with an unrelated-wallet control. Terminal-state and
explicit-reset controls pass. The matrix does not execute signing on all chains.

[PR #76](https://github.com/devdasx/oath-wallet/pull/76) adds a shared guard for
both removal paths. Pending Connect work blocks removal of an active wallet;
terminal records and unrelated wallets remain removable. No schema migration,
network behavior or full-reset authorization changes.

An intermediate repair blocked retention cleanup for wallets already removed
by older versions. A fifth test at `610f2fbcfa1b9a08bf9cfd9b439247324bf5366a`
reproduces that compatibility regression with seven failing assertions.
Final repair `0e91ce56f91ef56b3e45629967e01e449be0052f` preserves legacy
already-removed cleanup after retaining the original ordinary-send guard.
This exception matters because cleanup occurs during unlock after encrypted
wallet contents expire. The failing intermediate evidence is retained.

All five final methods pass. Full database tests: 744 pass, 72 explicit skips.
Diagnostics: 119 pass, two skips. Public-source validation, diagnostics coverage,
secret scan and unsigned generic iOS Release compilation pass.

## Limits

Already-removed legacy records can still be purged; the fix cannot recover
journals already deleted. The vault and SQL deletion steps are not one atomic
transaction, and concurrent signing/removal interleavings remain a separate
review area. No UI, simulator, physical device, live ledger or App Store
operation is included. The original tagged baseline is not retroactively fixed.
