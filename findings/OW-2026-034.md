# OW-2026-034 — A provider could keep a bounded read downloading after the limit

**Severity:** moderate availability impact. **Precondition:** a provider or its serving infrastructure controls the response to a wallet request. The effect reproduced was a delayed operation and continued receipt of unnecessary bytes. A provider that simply never sends the first bytes can still delay a request until its timeout. This finding establishes neither a device crash nor unauthorized signing.

## Reproduction

The [original transport](https://github.com/devdasx/oath-wallet/blob/8c2eec02bddeafd9fadb1aae1db9d49a67bc4a64/Packages/OathBitcoin/Sources/OathBitcoin/UTXOAPIProvider.swift#L207-L246) awaited a complete response before inspecting the HTTP status or testing the number of bytes. A 65,536-byte synthetic response with a 32,768-byte client limit remained open. The reader waited until the fixture sent its tail. An understated length header did not help. An allowed 404 also held the operation open for an irrelevant body. The host budget cannot reassign an occupied slot until the read returns. The regression observes the tail directly and checks URLProtocol cancellation on the repaired path. Fetching more than intended is observable without exhausting memory.

For fiat rates the fixture sends 139,264 bytes against a 131,072-byte maximum and then disconnects. The distinction is observable to callers. The old reader gets a connection error after consuming the oversized prefix. The intended 200 response classification is invalid data. The intended 503 classification is the original HTTP status. Bitcoin fee and previous-transaction lookups are also tested through their default network paths with both fallback hosts intercepted.

## Repair and limits

The [shared reader](https://github.com/devdasx/oath-wallet/blob/0e50b16ae1ced7934d57dba42d3e6e69ccf6cfc8/Packages/OathDiagnostics/Sources/OathDiagnostics/BoundedHTTPBody.swift) counts actual delivered bytes and cancels the transport on overflow or caller cancellation. It returns no partial payload to a decoder. Bitcoin releases its per-host slot on every exit and still records HTTP throttling. Allowed 404 returns from the header. A small, correlated RPC envelope is still inspected where the provider uses it for cooldown or temporary absence.

The same repair limits the default fiat, Bitcoin fee, raw parent, token RPC and app-update transports. Their own checks still decide whether a status means absence, provider outage, malformed data or an available result. The HTTP reader bounds the bytes it accumulates in its returned Data object. Foundation may read ahead or allocate backing storage. Large legal responses, decoding allocations, redirects and native framework internals need separate assessment.

To reproduce, run `python3 scripts/checkout.py`, then `python3 scripts/provider-response-budget.py MODE .work/source --scratch .work/MODE-build --output evidence/local/MODE` for each of `bitcoin`, `rates`, and `fallbacks`. The fixture bytes are identical on both revisions. Each case executes in its own macOS process with external networking denied. The pinned dependencies are fetched during build preparation.

**Verified in public source.** Eight failures and seven controls on the test-only baseline. All fifteen cases passed on the fix.
