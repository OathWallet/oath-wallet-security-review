# OW-2026-055 · Contract verification uses incorrect lengths and accepts malformed returns

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

Severity is low for the current application. Direct tests confirm errors in the bundled contract encoder and internal EIP1271 verifier. Application calls into the verifier have not been found. The provider remains a trust boundary even with correct parsing.

The original contract-call encoder declares a 65-byte signature for every input length and applies incorrect padding. Its fixed-hash helper can trap on an oversized digest. The verifier accepts any string beginning with the success marker, including malformed data, and rejects uppercase hexadecimal forms of a valid return. [Original encoder](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/Vendor/Reown/Sources/WalletConnectSigner/Ethereum/EIP1271/ValidSignatureMethod.swift#L5-L20) · [Original reply check](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/Vendor/Reown/Sources/WalletConnectSigner/Ethereum/EIP1271/EIP1271Verifier.swift#L25-L30).

A variable signature must retain its actual length and bytes. Nine of ten ethers-generated vectors differ from the original implementation. The repaired encoder matches all ten. Wrong-sized hashes fail before HTTP calls, and the shared fixed-hash encoder rejects oversize data instead of trapping. Replies must be an exact supported encoding of the marker. Exact four-byte legacy replies remain accepted alongside standard ABI words.

The original fixed-hash oversize case traps. The production verifier request and response tests fail before repair and pass afterward.
