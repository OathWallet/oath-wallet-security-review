# OW-2026-049 · Receive and change could issue an address beyond complete discovery

Oath scans up to 100,000 addresses per HD branch and requires a full gap of 20 unused addresses after its last payment. Index 99,979 is the last payable index with room for that gap. The public build 103 receive and change writers both returned and marked index 99,980 issued. If that address received a payment, only 19 unused addresses would remain before the scanner stopped. The wallet's next complete scan of that branch would fail. The key remains derivable. No key loss, network transaction or funded address was used in this review.

**Reproduction.** The host tests used the real Bitcoin key derivation and database APIs. They inserted the derived address at index 99,978 as used, obtained and marked the next address used, and requested a further address. The release returned the extra address and persisted its issued row on both branches. All four expectations failed. A separate small-cap test exercised the real scanner with synthetic funding history on either side of the equivalent boundary. It accepted the last payable address and returned the discovery-limit error for the next one. Severity is low given the unusually large branch required. [Before/after records and fixture](../evidence/5.0.1-build103/bitcoin-indices/focused.json).

**Repair.** The two allocation paths now share the scanner's address-count limit and reserve the trailing window before writing. Reserved change cannot consume that window. Fixed-key branches continue using their sole address. Coins already received outside the configured scan capacity require separate recovery assessment. [Wallet PR 62](https://github.com/devdasx/oath-wallet/pull/62).
