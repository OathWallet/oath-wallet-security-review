# OW-2026-002 — Missing aezeed bridge build source

Classification: **Assurance/provenance gap**, not a demonstrated cryptographic flaw.

The baseline `Packages/OathAezeed/README.md` instructs builders to run
`Tools/AezeedBridge/build.sh`, but the pinned public Git tree contains no such
directory. The app instead links bundled static archives. Hashing an archive
does not show that it was built from the documented LND implementation.

Required repair: publish the bridge, headers, pinned Go dependencies and fixture
generators; build them in isolation and compare generated public vectors with
the checked-in fixtures. Record archive reproducibility separately. Do not
claim historical binary equivalence merely because a fresh build succeeds.

Until source and validation are published, upstream implementation coverage and
source-to-binary equivalence remain unproven.

The bridge source, pinned Go modules, generators and regression tests are now
published at `ae5a35cec58f51bcfd6de3cd55950b47fa055a51`. Go race tests and vet
pass, and regenerated public seed fixtures equal the checked-in fixtures.
However, all three reconstructed archive hashes differ from their historical
counterparts. The historical binaries were retained unchanged. Source omission
is repaired; historical binary equivalence remains unresolved.

## Reproducible replacement (progress 9)

Commit `f7441b85d5216b702dde490eb027aece1a6cfb5a`, merged through
[PR 8](https://github.com/devdasx/oath-wallet/pull/8), replaces all three bundled
archives with reproducible builds. Two isolated builds match all ten framework
files and the checked-in outputs. The original timestamp and plist-order
mismatches remain in [the evidence](../evidence/aezeed-reproduction).

Seven bridge/package cases, 22 wallet integration checks, 27 targeted Bitcoin
tests (one skip), 118 diagnostics tests (two skips), independent AES primitive

[scope and commands](../review/AEZEED-REPRODUCIBLE-BUILD.md).

The new source-to-new-archive relationship is verified with the recorded compiler
and SDK. The historical shipped archive relationship is still unproven, so the
finding retains an explicit open historical limitation. No App Store binary was
uploaded, replaced, or verified by this repair.

## Historical comparison at progress 52

We rebuilt the earliest published bridge source under Go 1.26.5 and Xcode 27.0 and compared all three original release slices. Every C object was identical by full bytes. In each Go object, every byte of the executable section outside the embedded build-ID string matched, as did every raw section relocation record. The new build omitted four VCS fields present in the historical module information, including the flag identifying a modified checkout. Differences in read-only data were confined to that module information and adjacent zero padding. The writable data differed only in the length stored for runtime.modinfo. Debug data, symbol tables, load commands, Go build IDs and full archive hashes still differ. This materially narrows the historical gap but does not identify the original uncommitted inputs.
