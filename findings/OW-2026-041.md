# OW-2026-041 — Two recipient formats accepted a non-ASCII lookalike

Low severity, address-input validation. Replacing ASCII K with U+212A in an otherwise valid uppercase CashAddr or Litecoin Bech32 string passed Oath’s public recipient decoder. Case conversion transformed the character before alphabet validation. The test produced the same locking script as the ASCII spelling. There is no demonstrated transfer to a different recipient.

The shared decoder now checks printable ASCII and the maximum input size before dispatching by chain. Uppercase and lowercase valid encodings still derive the same locking script. The regression expected two rejections and recorded two failures on the unmodified production source. Both were rejected after the repair.
