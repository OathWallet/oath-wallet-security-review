# OW-2026-052 · A competing backup creation could be overwritten

The [original writer](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/Packages/OathCloudBackup/Sources/OathCloudBackup/CloudDrive.swift#L90-L110) treated a missing destination as permission to atomically replace the file later. That left a window for another process to create a different backup after the check. In the observed unsynchronized race, both writers reported success and the first file was lost. The old writer also replaced a dangling symlink already present at its destination. Severity is low because the competing writer requires write access to the backup directory and the filename must coincide. No live iCloud service participated.

The original stress run reproduced the lost update. Another run with different scheduling did not. Both observations remain in the record. The deterministic replay installs an exclusive competing file precisely between the original check and publication and applies the same interleaving to the repaired writer. The other writer's ordinary exclusive create and the code under test perform actual filesystem operations. [Reproduction script](../scripts/cloud-file-boundaries.py).

[PR 64](https://github.com/devdasx/oath-wallet/pull/64) prepares the encrypted bytes in a private replacement directory on the destination volume, then installs the complete file using an exclusive rename. If the destination already exists, the writer compares its contents through the bounded descriptor reader. Matching ciphertext makes a retry idempotent. Different content produces a conflict and the existing file is preserved. Errors other than an existing destination propagate. The tests establish behavior on the macOS test filesystem. iCloud File Provider interoperability and failures on volumes without exclusive-rename support remain unverified.

The source repair was merged after passing the complete [backup package tests](../evidence/5.0.1-build103/backup-file-identity/write/OathCloudBackup.json) and an unsigned generic iOS Release build.
