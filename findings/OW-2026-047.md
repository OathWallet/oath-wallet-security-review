# OW-2026-047 · An exhausted family number can interrupt wallet reopening

A locally constructed encrypted wallet vault reproduced a process trap on the 5.0.1 build 103 source. After authentication, the vault tried to assign a display number to an existing passphrase wallet. Adding one to the highest stored integer overflowed. The crash frame points to [the wallet family reconciliation loop](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/OathAtmosphere/Wallet/OathVaultEnvelope.swift#L220-L232).

**Impact and scope.** This is a local availability defect under extreme persisted metadata. The fixture sealed and reopened successfully before the crash. It establishes neither credential loss nor external authority to modify authenticated data. No real wallets were involved. Severity is low given the precondition.

**Reproduction.** Starting with a clean public wallet checkout and a separate checkout of this review, set the two paths in the following commands. The patch adds the fixture to the host test alone.

```sh
git -C "$WALLET" checkout --detach c7acd23bb139864a40273f405d18b479589d2b20
git -C "$WALLET" apply "$REVIEW/evidence/5.0.1-build103/family-index/tag-failure.patch"
(cd "$WALLET" && python3 Tools/CheckMultiWallet.py --envelope)
```

The host process terminated with SIGTRAP. The crash reporter identified a Swift arithmetic overflow in the named production function at line 231. The [sanitized crash receipt](../evidence/5.0.1-build103/family-index/reproduction.json) contains the original report hash and the production frame.

**Repair.** [Wallet PR 60](https://github.com/devdasx/oath-wallet/pull/60) keeps the counter monotonic for new wallets. If numbering is exhausted, creating a new BIP39 passphrase wallet or Electrum seed-password wallet returns a normal error before writing a new secret. Reconciliation can still reopen existing wallets. It keeps their known labels and, where a label is missing, uses a number unoccupied by either a vault member or a saved database label. This fallback applies only when there is no higher representable value. Derivation and signing inputs are unaffected.

The repaired envelope harness passed 87 checks. Boundary cases include a missing number, a label reserved by the database, preserving the last representable number and rerunning reconciliation without renumbering.

The BIP39 passphrase suite passed 87 checks and the Electrum seed-password suite passed 90. The unsigned generic iOS Release build succeeded. The tested source tree matches the public merge in PR 60.
