# OW-2026-068 — Sui history restart overflows on a malformed checkpoint

Status: **Fixed and retested in source; hosted replay pending.**
Severity: **Low, availability.** No signing, key disclosure or fund loss is demonstrated.

At `05e7917f0a3c26072b1a6b88d2e9e4a0d0310427`,
`Packages/OathDatabase/Sources/OathDatabase/SuiLedger.swift:118–124` adds one
to the persisted oldest checkpoint without checking integer overflow.
`SuiDecoding.transaction` accepts the nonnegative Int64 maximum from the
untrusted JSON checkpoint field. `commitSuiPage` saves it to the history cursor.
A later expired cursor reaches this addition through `SuiSynchronizer.startHistory`.

The deterministic host reproduction decodes synthetic provider JSON through the
production decoder, commits the resulting page through the production SQLite
API, then invokes the restart method. The original test process terminates with
SIGTRAP (exit -5), before XCTest can finish the method. A representable
`Int64.max - 1` control succeeds. This is malformed-response handling, not a
claim that an honest Sui node currently produces that checkpoint. The full
transport/synchronizer sequence is source-traced, not executed by this fixture.

Repair `b3f1f6af98bedfe850d390cac684a563c598e3ac` uses checked addition and
rejects negative or overflowing checkpoints with `SuiError.malformed` before
writing a cursor. The identical method passes after repair and verifies that
rejection preserves the cursor, including after reopening the database.
The representable boundary remains accepted. No migration or stored identity changes.
The repair contains the failure; it does not silently erase or repair a previously
saved malformed checkpoint. Existing history error handling records that failure.

No simulator, live provider, physical device or App Store operation is involved.
