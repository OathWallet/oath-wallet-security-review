# OW-2026-075 — Solana WalletConnect accepts stale or malformed RPC contexts

Severity: **Low, provider-response validation and review reliability.**
Status: **Fixed in public source and retested locally and in GitHub Actions.**

Baseline: `02ec5362c188134c42632c555ed5401218d653cb`, public 5.0.3 (105).
Repair: `e888b220d7c245aaac5b3911ed4f7c72ca5743bd`.
Merged through [PR #100](https://github.com/OathWallet/oath-wallet/pull/100),
commit `3338d294f08388655ffd4cfc3e50656f304e1c6c`. The merged application
inputs match the repair; additional changes are confined to the separate website.

The production WalletConnect client sends `minContextSlot` but does not validate
it against several response contexts. Blockhash validity, lookup accounts,
simulation, fees and mint metadata can be accepted with a missing, malformed or
older slot. Fee requests also used the initial requested minimum even when the
simulation had advanced. The native send client already has the required
`value(_:slot:)` validator; these WalletConnect reads bypassed it.

For example, a review requests a minimum of 100 and reads accounts at 123. A
simulation or fee response at 122 is accepted. A simulation at 125 still produces
a review slot of 123 and a fee request minimum of 100. The validity helper accepts
a `false` blockhash result from slot 99 even when asked for at least 100. The
pending-transaction recovery caller uses a false validity result as one condition
for expiring an old pending entry, after further status checks. The caller was
traced in source; no full application journal-expiry execution is claimed.

Expected behavior: reject a context without a numeric unsigned slot, or one below
the request's minimum. Simulation must not precede the pre-state account read;
fee and mint requests must not precede the simulated state. Invalid contexts must
throw rather than become a review or a blockhash-expiry decision. A fresh false
blockhash result remains false; a fresh missing mint retains exact base units
without inventing decimals.

The repair reuses the native validator at the five WalletConnect response
boundaries, advances subsequent requests to the simulation slot, and records
that slot in the review. Existing simulation-error, fee-limit, nonce, signature,
cluster and preflight checks remain intact. Existing test transports now return
the context fields required by the RPC contract.

The identical eleven-method fixture records three passing controls and eight
failing methods before repair. The repaired package passes all 52 selected
Solana methods, including all eleven regressions, with networking denied.
Detailed immutable source bindings, commands and validation are in the
[reproduction report](../review/SOLANA-RPC-CONTEXT.md).

The low rating reflects acceptance of incoherent provider responses. The tests
inject those responses; they do not establish control of an app-configured
provider, a remote dApp exploit, unauthorized signing, loss of funds, or a
cryptographic guarantee of provider freshness. A dishonest provider can lie
about both its slot and value. This is a validation improvement, not an
independent state-verification mechanism or complete wallet audit.
