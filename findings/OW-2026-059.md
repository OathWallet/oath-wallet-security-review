# OW-2026-059 — A canceled backup read changes a newer batch's progress

**Severity: low; backup-status integrity/reliability.** A late database-read
failure from a canceled Back Up All Wallets operation can set the newer batch's
error and advance its completion count. This does not demonstrate backup
corruption, key disclosure, an authorization bypass or a false persisted upload.

## Cause

In 5.0.1 (103), `OathAllWalletBackupModel.finished` checks operation identity and
cancellation before reading the current backup record, and again after a
successful read. Its catch path lacks the second check. If cancellation/new-batch
creation happens during that read, an eventual failure sets `failure = "failed"`
and increments `finishedCount` for the obsolete operation. A later current
completion can then count two completions for a one-wallet batch.

Source: `OathAtmosphere/Home/OathAllWalletBackupPage.swift`, the `finished`
callback. The prior public repair tree `00d26c005fbc3f811615b23b865bb50ef7b6619f`
retains the same source bytes as the tagged baseline. The service calls this
callback after a preparation completes; cancellation does not prove an already
started asynchronous database read cannot finish by throwing.

## Reproduction

The host fixture extracts the **unchanged production model** from the source file;
it does not copy its state machine into the test. The SwiftUI page is omitted.
Database, service, diagnostics and vault are synthetic boundaries. Continuations
hold the old read until a new batch has entered its own read, then release it
with success or failure. Completion barriers wait for the production callback to
return. There are no guessed sleeps, live iCloud requests, credentials or devices.

The exact same fifteen named cases yield **12 passes / 3 failures before** and
**15 passes / 0 failures after**. The success path is a passing control; the old
failure contaminates the error and counter. Three additional controls prove a
current read failure still appears and counts once. The first exploratory
12-case failure and its Swift top-level trap are retained separately from the
final normal-exit fixture.

## Repair and validation

[Public repair #73](https://github.com/devdasx/oath-wallet/pull/73),
`a904515793b087289140e4411924f030b3fe61ff`, adds the existing operation and
cancellation guard to the catch path before changing state. It leaves committed
backup jobs, persistence formats, encryption and valid error reporting unchanged.
The narrow replay passes, as do public source validation, diagnostics coverage,
a zero-match secret scan, 119 diagnostics tests (two skipped) and unsigned generic
iOS Release compilation. Merge `cfd43d36f6e1ee58845005bd817b069096843030` includes
concurrent Website-only changes; all other tracked files match the tested commit.
The manifest lists that delta. No App Store availability or full UI/cloud result
is claimed.
