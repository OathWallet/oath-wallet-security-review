# OW-2026-033 — A peer's unrelated Bitcoin signature could be returned as an approved result

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

**Severity moderate, signing-result integrity and availability.** A dApp supplied a native SegWit partial signature, or a Taproot key signature, made for a different transaction spending the same synthetic coin. After approval the wallet returned the old signature. The old verifier also admitted a signed packet whose unlocking data was empty or belonged to a different transaction. An independent Bitcoin Core node rejected both contaminated spends. No unauthorized spend, private-key disclosure or production attack was demonstrated.

**Route.** A peer's signPsbt request enters the usual Bitcoin WalletConnect review. The wallet checks ownership, funds and the displayed outputs. When signing, it passes a scoped PSBT to BDK. BDK intentionally skips a key it regards as already signed. Oath checked that a final field existed and later compared the unsigned transaction and fee, which do not authenticate a final signature. The database calls that same verifier before journaling a broadcastable result and when decoding an existing record. [Original signer](https://github.com/devdasx/oath-wallet/blob/e4d48f85ee43236c388b987dfec52feadfae2551/Packages/OathBitcoin/Sources/OathBitcoin/BitcoinConnectPSBT.swift#L209) · [Original verifier](https://github.com/devdasx/oath-wallet/blob/e4d48f85ee43236c388b987dfec52feadfae2551/Packages/OathBitcoin/Sources/OathBitcoin/BitcoinConnectMessage.swift#L62)

**Repair.** Only the current requested input has its peer-supplied ECDSA partials and Taproot key signature removed before local signing. The final proof is checked on the signing path and during journal verification. The check reconstructs the requested signatures as partials in a temporary PSBT anchored to the approved transaction's validated previous outputs. BDK's bundled miniscript interpreter checks the resulting script against those outputs. Oath compares the reconstructed script and witness with the returned data, including the requested Taproot hash mode. A previously finalized map would skip that interpreter path; the verifier therefore starts with fresh requested-input maps. Its internal markers never enter the returned packet. [App PR #45](https://github.com/devdasx/oath-wallet/pull/45) · [Proof implementation](https://github.com/devdasx/oath-wallet/blob/0e611a5408cfa02c8463b4bcd74a0164522cf7a3/Packages/OathBitcoin/Sources/OathBitcoin/BitcoinConnectProof.swift)

**Reproduce.** Run the signature pair, Core installer and independent Core comparison described in the [review notes](../review/BITCOIN-SIGNER-AND-CORE.md). The identical unit fixture covers peer partials, journal-admissible empty data, replayed final signatures in all four supported address types, and substitution of a valid signature using another hash mode. The Core fixture funds disposable outputs, changes the recipient amount for the stale signature, then submits the signed response for the original approval to Core. Positive controls exercise legacy and nested SegWit. All network activity in the test process is restricted to its isolated loopback RPC port. No public network accepts or sees a test transaction.
