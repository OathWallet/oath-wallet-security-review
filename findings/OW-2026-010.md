# OW-2026-010 — Delegation sizing helper can overflow its authorization nonce

Severity: **informational**. This is a public API input-validation defect.
A direct malformed call crashes a host process, but no reachable app-level
crash, fund loss, secret disclosure or signing bypass was established.

## Root cause and reachability

At `6124254d43ee7a98d4a364639671ccfc52155396`,
`Packages/OathAnkr/Sources/OathAnkr/EVMSendCrypto.swift:25–31` adds one to the
outer nonce when encoding an EIP-7702 self-sponsored delegation removal.
`unsignedBytes` is public and also used to size provisional fee estimates;
it does not require a fully validated/funded plan. Passing `UInt64.max`
directly traps on arithmetic overflow. Passing `UInt64.max - 1` serializes an
authorization nonce that the existing validation contract rejects.

[EIP-7702 authorization processing](https://eips.ethereum.org/EIPS/eip-7702#behavior)
requires the authorization nonce to be below `2**64 - 1` and processes it after
the sender nonce increment. The helper guard preserves that existing boundary.

The normal quote caller checks `nonce < UInt64.max - 1` before fee sizing
(`EVMSendClient.swift:277,358`). Signing and verification validate the plan
before encoding; `authorizationDigest` also checks the bound. Therefore a
malicious provider reaching those traced app paths was **not** shown to reach
the overflow. The defect is at the helper API boundary, not proof of a remotely
exploitable application failure.

## Reproduction and repair

Regression-only commit `3cfa6168aac85b5e7c7c42daa4bf7b37e23276ce` adds four
cases without changing production code. Three network-denied repetitions each
show:

- Maximum nonce: process terminates with SIGTRAP. A separate LLDB run identifies
  `Swift runtime failure: arithmetic overflow` in `EVMSendCrypto.fields` at
  the nonce-addition line. The evidence runner requires that stack evidence;
  an arbitrary crash does not qualify as this reproduction.
- Maximum minus one: the expected rejection assertion fails because no error
  is thrown.
- Valid delegation sizing: nonces 0, 7 and maximum minus two encode even with
  an unfunded provisional plan.
- Ordinary legacy and type-2 serialization: unchanged by the authorization
  nonce constraint.

Fix commit `2e51f0bcd3e710c35a1d78ee93746f6a8f202fdc` adds the existing nonce
bound immediately before delegation encoding. It throws the existing signing
error rather than overflowing or encoding the disallowed authorization nonce.
It deliberately does not impose full funding validation on the sizing helper.
There are no wallet, backup, database, authorization or transaction-format
migrations. The same four-case fixture passes in all three post-fix processes:
12 case passes, no traps or invalid acceptances. Fixture hashes match before
and after; compiled binary hashes differ.
