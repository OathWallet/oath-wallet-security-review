# OW-2026-027 — Concurrent history operations accepted duplicates and erased replacements

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

Severity: **low, SDK pending-request integrity and availability**. Controlled
interleavings allow duplicate insert/resolve success and stale cleanup to erase
a newer record. No app-level duplicate signature, remote exploit or fund loss
was established.

## Affected source and expected behavior

Regression baseline `c1d12689cceb67d9bd4cfc76371082fe60da5893`, RPCHistory.swift:
- [set:91](https://github.com/devdasx/oath-wallet/blob/c1d12689cceb67d9bd4cfc76371082fe60da5893/Vendor/Reown/Sources/WalletConnectUtils/RPCHistory/RPCHistory.swift#L91): read-then-write accepts two inserts for one ID.
- [resolve:103](https://github.com/devdasx/oath-wallet/blob/c1d12689cceb67d9bd4cfc76371082fe60da5893/Vendor/Reown/Sources/WalletConnectUtils/RPCHistory/RPCHistory.swift#L103): validate-then-delete returns the same pending record twice.
- [topic cleanup:129](https://github.com/devdasx/oath-wallet/blob/c1d12689cceb67d9bd4cfc76371082fe60da5893/Vendor/Reown/Sources/WalletConnectUtils/RPCHistory/RPCHistory.swift#L129) and [expiry cleanup:174](https://github.com/devdasx/oath-wallet/blob/c1d12689cceb67d9bd4cfc76371082fe60da5893/Vendor/Reown/Sources/WalletConnectUtils/RPCHistory/RPCHistory.swift#L174): stale snapshots delete a newer replacement.

Expected: exactly one duplicate operation succeeds, and cleanup does not erase
another operation's newer replacement. Separate SDK factories share one storage
namespace, so synchronization must cover separate history instances.

## Repair and retest

Fix: `6d8fda366773726364b0cb8b389d793cd34bd0bd`. A shared recursive lock covers complete synchronous RPCHistory
operations and their nested reads. Storage formats and identifiers are unchanged;
network waits are outside the lock.

Before: 10 assertions across six failed cases; five controls pass. After: all
11 cases pass. The same production implementation is tested through a gated,
thread-safe memory-storage implementation; timing misses and unrelated failures
do not satisfy the baseline classifier. See [scope and commands](../review/RPC-HISTORY-ATOMICITY.md)
and [hashed original evidence](../evidence/history-atomicity/manifest.json).

SDK 240 passed/one skip; diagnostics 118 passed/two skips; unsigned iOS Release
compile passed. Cross-process access, direct storage writes and async response
generation binding remain unresolved. The repaired source is not a claim about
the installed App Store binary.
