# OW-2026-001 — JSON object collection limit

Severity: **Low**, bounded resource-policy inconsistency. No fund-loss or secret
disclosure exploit was established.

Affected baseline: `Packages/OathAnkr/Sources/OathAnkr/WalletConnectJSON.swift`,
object branch in `Parser.value(depth:)`, at the pinned baseline commit.
The array branch checks `collectionLimit`; the object branch did not.

Reproduce with the production parser:

```swift
try WalletConnectJSON.decode(Data("{\"a\":0,\"b\":0,\"c\":0}".utf8), collectionLimit: 2)
```

Expected: reject the third member. Baseline: accepts it. Independent byte,
depth and total-node bounds still limit the input. This is not unbounded memory
growth and is not rated critical.

Fix: check object member count before parsing each additional member, matching
the array branch. No wire-format, key-storage or derivation changes.

The audit harness performs 6,016 assertions, including a deterministic 2,000-case
generated/mutated corpus with seed `0x4f41544820261031`. Baseline: one failed
assertion. Fixed source: zero. Logs: `evidence/local/parser-baseline.log` and
`evidence/local/parser-fixed.log`. The application regression suite also checks
exact limits, nested objects, empty objects and arrays.

Publication and complete package-regression status are recorded in the report.

Fix published on the application review branch at
[`ae5a35ce`](https://github.com/devdasx/oath-wallet/commit/ae5a35cec58f51bcfd6de3cd55950b47fa055a51).
Production-parser host retest: 6,016 checks, zero failures. Full CI and main-branch
integration are separate pending gates. This is not an App Store fix claim.
