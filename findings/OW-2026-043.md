# OW-2026-043 · A queued metadata request can repeat a completed lookup

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

**Severity:** Low. A duplicate read consumes time and provider quota. The failing case did not access a funded account or produce a transaction.

**Affected source:** [PublicCheckTransport.send at the reviewed revision, lines 60–91](https://github.com/devdasx/oath-wallet/blob/8c4e1d5d3a14bec0b9ea3a1fd01c7611ea4dd707/Packages/OathAnkr/Sources/OathAnkr/PublicCheckProviders.swift#L60-L91). In a transport configured with one slot, the next waiter can run between permit release and the cache write. The expected count is one underlying request. The [archived assertion](../evidence/progress55/provider/ci-failure.log) reports two.

**Reproduction:** Run `PublicCheckProvidersTests.testQueuedMetadataReusesCompletedResponseWithoutRepeatingAccountProbes`. It queues twelve callers against an injected transport and counts the actual reads. The original CI failure was intermittent. A later 120-process run on the unchanged 5.0.1 parent passed all 120 times.

**Repair:** [PR 55](https://github.com/devdasx/oath-wallet/pull/55) stores an eligible successful response before releasing either permit. The unchanged single-slot case passed in 120 separate network-denied processes on commit `b337611405bbff7a8c6c7da4bebdeb850b228163`. The full OathAnkr host suite passed 1,323 cases and skipped 201. The fix is later than the pinned review target and the 5.0.1 release tag. [Package results](../evidence/progress55/provider/OathAnkr.json).
