# OW-2026-077 — Solana stake control changes omitted from signing review

Severity: **Medium, misleading transaction authorization.**
Status: **Fixed and retested in open public PR #117; not yet merged.**

Baseline: `393c29cbae673f60f1df6ac9636af908ae789649`, public 5.0.3 (105).
Repair: [`f857fa9ece0b290e1b9ab9cf5e3cb85ebacc045e`](https://github.com/OathWallet/oath-wallet/pull/117).

A malicious connected dApp can request replacement of a stake account's
withdrawal authority while the main review shows only the network fee. The
connected key must control that stake account and the user must approve/sign.
The replacement authority can later control/withdraw the stake subject to chain
activation and lockup rules. No signature bypass or approval-free theft is shown.

`WalletConnectSolanaClient.swift` previously modeled native balance changes only
for the connected wallet and SPL token balances/delegations. Stake Program account
bytes and stake-held SOL were ignored even when all writable accounts were fetched.
`OathWalletConnectSolanaViews.swift` consequently had no stake effect to display.
The same omission applies to stake withdrawals and state changes performed via
another program. The raw instruction screen and general warnings do not describe
this permission transfer. These facts support Medium severity, consistently with
OW-2026-073, rather than an unsupported High/Critical classification.

Expected: no unsupported stake control change may reach approval as a complete
fee-only preview. The small repair rejects direct Stake Program requests and
simulated stake-account changes, creation or closure. Other programs referencing
unchanged stake accounts remain allowed. Dedicated staking operations are now
unsupported through the generic review, rather than incorrectly summarized.

The production request-preparation and pre-signing paths both invoke this review.
Nine identical methods run on clean baseline and repaired packages: two baseline
controls pass and seven fail with 44 expected assertions; all 67 selected Solana
methods pass afterward, with zero skips and networking denied. Ten official SDK
legacy/v0 messages and synthetic stake states exercise the production code.
This proves the review omission and repair, not an executed on-chain exploit.

exploratory failures and limitations](../review/SOLANA-STAKE-AUTHORITY.md).
The whole-wallet audit remains incomplete. The repair is not claimed present in
the App Store build.
