# OW-2026-007 — Restored Ed25519 paths describe skipped derivation steps

- Severity: **low**, recovery metadata and interoperability integrity.
- Status: **fixed and retested in public source**; App Store delivery is not claimed.
- Affected application: [OathWalletRestoration.swift:68–74](https://github.com/devdasx/oath-wallet/blob/15174cdf8378816cad58310206146deeeede546d/OathAtmosphere/Wallet/OathWalletRestoration.swift#L68), and its curve-agnostic `validPath` helper.
- Dependency: [Wallet Core 4.8.4 HDWallet.cpp:139–150](https://github.com/trustwallet/wallet-core/blob/d40d24a63d92619167903369308bf0e2f7eb3a59/src/HDWallet.cpp#L139) ignores failed child derivation returns; the Ed25519 non-hardened branch in `trezor-crypto/crypto/bip32.c` returns failure without changing the node.
- Fix: [`02a6e8ab66c7629dcb9dd36637c683457e821d98`](https://github.com/devdasx/oath-wallet/commit/02a6e8ab66c7629dcb9dd36637c683457e821d98), [PR 9](https://github.com/devdasx/oath-wallet/pull/9), merged as `b3d70526734da9c69294cdb00fe2663387378b3c`.

## Cause and demonstrated impact

A backup containing `m/44'/501'/0'/7` passes syntactic restoration validation.
For the seven tested Ed25519-family chains, Core derives the same private key as
`m/44'/501'/0'`, silently skipping the unsupported `/7`. Oath previously retained
the longer path in the restored account, describing a derivation that did not
actually happen. Mixed paths skip each unsupported non-hardened step; an entirely
non-hardened path recovers the root key.

The defect requires nonstandard backup account metadata. Normal all-hardened paths
are unaffected. It can cause disagreement with other recovery tools and misleading
account metadata. The evidence does **not** establish unauthorized signing, secret
exposure, or fund theft. No production wallet or funded account was used.

## Repair

Restoration validates every path component before canonicalizing paths for Aptos,
NEAR, Solana, Polkadot, Stellar, Sui and TON. It records only the steps that the
pinned Core actually executes. It never adds hardening to a child: that would
change the recovered key. A canonical root `m` is accepted for these chains so a
repaired old backup can be exported and restored again. Account identity and a
matching selected Solana receive path are preserved consistently. Imported keys,
multisignature descriptors and paths for other chains retain their existing handling.

Existing on-device vaults are not migrated. The repair applies when restoring
backup metadata. The upstream ignored-return behavior itself is unchanged, and
other derivation callers and failure modes remain in the review scope.

## Real before/after evidence

The same committed regression test and host entrypoint were applied to the prior
production source `15174cdf8378816cad58310206146deeeede546d` and the fixed source.
The [before-input manifest](../evidence/restored-path/before-inputs.json) records
production and fixture hashes. Before: the first new effective-path assertion
traps, runner exit 1. This is **not** a complete baseline corpus pass/fail count.
After: **140 checks pass**, including 28 existing restoration cases and 112 new
assertions covering seven chains and four path pairs. The tests execute production
restoration, backup encryption, vault persistence and SQL handling; they substitute
Wallet Core address derivation at the host boundary.

Separately, the actual distributed Core simulator framework compared keys in memory:
**112 equalities**, seven chains × eight original/effective path pairs × two public
BIP39 test-vector seeds. No private-key bytes were logged. This is a minimal C ABI
process, not the complete app's restoration UI. The simulator was shut down afterward.
It proves the sampled framework behavior, not source-to-binary equivalence or an
exhaustive cryptographic property.

Diagnostics passed 118 tests with two explicit skips. Public-source/secret scans,
diagnostics coverage, and unsigned generic iOS Release compilation passed on the
fix commit. [Results](../evidence/restored-path/results.json),
[logs and manifest](../evidence/restored-path), and
[reproduction instructions](../review/RESTORED-PATHS.md) preserve the exact scope.
