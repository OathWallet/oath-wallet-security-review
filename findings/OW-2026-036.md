# OW-2026-036 — The last normal BIP32 address could not be derived or spent

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

**Low severity, availability and interoperability.** Someone recovering an address explicitly derived at index 2,147,483,647 on a supported HD branch could encounter a failure in Oath despite holding the correct seed. Reaching this index by ordinary sequential use is impractical. The failure does not disclose a key or authorize another signer.

The original half-open range check at [BitcoinKeys.swift line 217](https://github.com/devdasx/oath-wallet/blob/3c657667fb7091b9162a8d808f51e0c450bf1dc7/Packages/OathBitcoin/Sources/OathBitcoin/BitcoinKeys.swift#L217) excluded the legal end of a one-element range. Four further checks rejected the child itself in plan validation, ordinary leaf export, Electrum export and multisig signing. The [five-site repair](https://github.com/devdasx/oath-wallet/commit/7ecfa2c163704d363ebe6dc16b60151dc8a7cd78) uses the same hardened boundary with the comparator appropriate to each representation.

Four synthetic before-cases threw invalidAddress. All four and the pre-existing passing negative control succeeded after the repair. The corpus binds each original test source to the same bytes on both revisions and checks the precise failure before accepting a reproduction.
