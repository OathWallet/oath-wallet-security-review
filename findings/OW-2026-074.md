# OW-2026-074 — Solana wire offsets assume a zero-origin Data buffer

Severity: **Low, parser robustness and availability.**
Status: **Fixed in public source and locally retested; hosted replay succeeded and downloaded evidence verified.**

Baseline: public 5.0.3 (105), commit
`ce9d27baf5e6d81452b46d5a2b5688da2fcd93d7`.
Repair: `4b29aa2d73582c7b0c037723726a7a9972c7700a`.
Merged through [PR #97](https://github.com/OathWallet/oath-wallet/pull/97),
merge commit `02ec5362c188134c42632c555ed5401218d653cb`.
The tested repair and merge have identical source trees.

`WalletConnectSolanaTransaction.init(bytes:account:)` converts the input to an
array for parsing, which makes parser offsets zero-based. It then extracts the
message from the original `Data` using those offsets. A `Data` slice can retain
its parent's nonzero `startIndex`. The same bytes therefore produce a different
message at offset 1, and a higher offset can trap rather than throw.
`verifySigned` and `walletConnectSubmit` also index caller-owned buffers using
transaction-relative signature offsets.

The public initializer accepts `Data` without a zero-origin precondition. A
caller can reproduce the defect by prepending synthetic bytes to a valid SDK
transaction and using `dropFirst` to pass the original transaction as a slice.
Expected behavior: identical transaction/message/signature bytes regardless of
the backing collection's origin, while invalid signatures remain rejected.

The normal WalletConnect JSON decoder creates ordinary base64-decoded buffers.
No remotely triggerable exploit through that normal path, unauthorized signing,
fund movement, or secret disclosure was established. The low rating describes a
confirmed public-API robustness defect, not a proven wallet-drain vulnerability.

The repair normalizes bounded transaction input before storing or slicing it,
uses the parsed normalized bytes for signature comparison, and normalizes a
successfully verified submission before extracting its expected signature. The
1,232-byte bound, exact message matching, cosigner preservation, signature
verification, cluster validation, and mandatory preflight remain in place.

The paired fixture covers legacy, versioned, lookup-table and partially signed
multisignature SDK vectors, with slice origins 1, 128 and 1,024. Before the repair,
two control methods pass and three slice methods fail, including SIGTRAP. After
the repair, all five methods and adjacent Solana host tests pass. Detailed counts,
source hashes, commands and publication status are recorded in the
[reproduction report](../review/SOLANA-BUFFER-ORIGIN.md).

No App Store delivery or simulator/physical-device execution is claimed. This
finding does not close the remaining whole-wallet or dependency review gaps.
