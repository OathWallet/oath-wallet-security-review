# OW-2026-046 · An interrupted import could activate a wallet from a different recovery format

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

**Impact.** A person importing words that are valid under both aezeed and BIP39 could change the format after an interrupted save yet be shown the wallet for the earlier choice. The two interpretations have different Bitcoin receiving addresses. The same identity error allowed a private-key retry at the vault API to return the previously committed phrase wallet. An external party controlling a request UUID, a disclosure of secret material and any funds movement were not demonstrated. Severity is moderate for wallet identity and recovery correctness.

**Affected path.** The [5.0.1 import screen](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/OathAtmosphere/Home/OathWalletSwitcherSheet.swift#L330-L378) rotated its request identifier for text edits. Changing only the selected interpretation left the identifier intact. After the encrypted write but before SQLite activation, a failure can leave a valid member in the vault. The [wallet actor](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/OathAtmosphere/Wallet/OathWalletVault.swift#L1521-L1558) selected a previous member by request ID even when its recovery material differed. The multisignature branch already checked the material.

**Reproduction.** The fixture inserts conflicting public metadata for a new UUID, commits a synthetic overlapping phrase as aezeed, observes the metadata failure, removes the injected conflict, and submits explicitly selected BIP39 under the same UUID. The original wallet actor accepts that change and also accepts an unrelated synthetic private-key request. Both unexpected successes were reproduced against the tagged production code. The separate test fixture is the only substituted source file in the build 103 replay. Wallet storage and biometric services are in memory, and the database is a temporary SQLite file.

**Repair and controls.** The import draft now retains the same UUID for unchanged input and rotates it for changes to the words or chosen format. The actor checks a previously committed request against credential kind, mnemonic format and material, or private-key identity and chain scope, before activation. A rejected retry preserves selected wallet, encrypted bytes and SQL state. A matching retry repairs the missing SQL records. A fresh BIP39 choice obtains its own wallet and its independently expected Bitcoin receiving address. [Regression fixture](https://github.com/devdasx/oath-wallet/blob/270b3c3c20af17192b571bd176ecee1313084907/Tools/CheckAezeedImport.swift) · [Source repair](https://github.com/devdasx/oath-wallet/commit/e1857158db600fc171cdcca7cedd37da2722f8ad) · [Reproduction command](../scripts/import-retry-identity.py).

The host test exercises the production wallet actor, import validator, encrypted vault and database with public inputs. The harness has a substitute BIP39 display adapter and checks the two actual Bitcoin receive results separately. The UI state transition is exercised through the production draft model; it does not constitute a device or visual test.

The [shared before/after fixture](../evidence/5.0.1-build103/import-retry/result.json) reproduced two unexpected successes on the release tag. All 37 cases passed after the initial repair. A further internal API control passed an empty mnemonic with the request ID of a private-key wallet. Both stored mnemonic fields were empty, so the equality check incorrectly matched. The regular phrase-entry UI cannot construct this input. After rejecting empty input at the API, all 38 cases passed. [Public wallet change](https://github.com/devdasx/oath-wallet/pull/58).

The final merge matched the tested source tree. The 791-case general wallet harness and the 38-case focused harness both passed on the final candidate. The unsigned generic iOS Release build passed. [Final checks and commit identities](../evidence/5.0.1-build103/import-retry/final.json).
