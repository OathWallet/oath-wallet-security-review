# OW-2026-045 · Upgrading during an interrupted wallet reset could block startup

> Current audit target: [5.0.2 (104) prerelease](../review/RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

Moderate availability impact. If an older database still had wallet rows and a pending reset, the backup-reminder migration could keep the database from opening. Normal startup needs the database open to finish the reset. The reproduction did not show information disclosure or a lost key.

The [existing-wallet reminder migration](https://github.com/devdasx/oath-wallet/blob/8fdf4494f62219348ec0605d7fa38285c0fd058e/Packages/OathDatabase/Sources/OathDatabase/Schema.swift#L1513-L1520) wrote to wallet rows while the reset's own SQLite trigger protected them. The error was “Wallet reset in progress.” This migration is present in the 5.0.1 (103) tagged source and was introduced after the historical review target.

Three real database upgrade fixtures failed before the fix. They are separately identified in the [failed host suite](../evidence/progress56/packages/OathDatabase/OathDatabase.xml). The [repair](https://github.com/devdasx/oath-wallet/commit/5071662dc0700d7011795035aa14b5795a4a1e3a) skips setting backup reminders for rows that are about to be erased when a reset is pending. The existing write fence stays active. Already-applied migrations retain their original identifiers.

The three identical fixtures then passed. The full database suite on the fixed source passed 732 tests with 72 explicit skips. [Targeted before/after](../review/BITCOIN-JOURNAL-AND-RESET.md) · [Full fixed suite](../evidence/progress56/packages/fixed-database/OathDatabase.json).
