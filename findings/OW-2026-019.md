# OW-2026-019 — Account constructor accepted an invalid separate chain argument

Severity: **low**, SDK API input-contract correctness. No app exploit or signing
bypass has been demonstrated; Oath's inspected approval path uses the other,
typed-chain constructor.

## Reproduction

The [baseline Account initializer](https://github.com/devdasx/oath-wallet/blob/764dd608519e8f30f60e3dea4a553c1def2f8c07/Vendor/Reown/Sources/WalletConnectUtils/Account.swift#L78)
joined arguments before validating them:

```swift
Account(chainIdentifier: "eip155", address: "1:synthetic")
Account(chainIdentifier: "cosmos", address: "cosmoshub-4:synthetic")
```

Both returned an account, despite the invalid chain and colon-containing address.
The expected result is `nil`: each argument must satisfy its own contract.
The fixture uses synthetic strings, without credentials or network requests.

Fix commit: `8e5b6b0f565026951d7cef9435258daa0b02b9b2`.

typed-chain constructor. All previously valid argument pairs retain their
original output. Whole-string decoding and stored identities are unchanged.
