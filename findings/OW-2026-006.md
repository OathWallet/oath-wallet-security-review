# OW-2026-006 — Pairing URI query boundaries change during decoding

- Severity: **low**, parsing/integrity and pairing availability.
- Status: **fixed and retested in public source**; not an App Store delivery claim.
- Affected source: [WalletConnectURI.swift, lines 44–49, 85–104](https://github.com/devdasx/oath-wallet/blob/e352f56d0fb3be035c3600e646e3f9133adb9ef4/Vendor/Reown/Sources/WalletConnectUtils/WalletConnectURI.swift#L44).
- App entry: [OathWalletConnectService.pair, lines 204–209](https://github.com/devdasx/oath-wallet/blob/e352f56d0fb3be035c3600e646e3f9133adb9ef4/OathAtmosphere/Scanner/OathWalletConnectService.swift#L204).
- Fix: [`a65601b78f86e33ebae08a754035d69c1f5f5e43`](https://github.com/devdasx/oath-wallet/commit/a65601b78f86e33ebae08a754035d69c1f5f5e43), [PR 6](https://github.com/devdasx/oath-wallet/pull/6), merged as `4694c68b87dd5f0ebeda8c8298fb03b5f2ce2b58`.

## Cause and reproduced behavior

The app validates an opaque `wc:` URI with `URLComponents`, rejects duplicate
fields, and passes the original string to the SDK. The SDK decoded the entire
URI twice before query parsing, then kept the last value of duplicate names.
Consequently a query value containing `%26symKey%3D` was reinterpreted as an
additional `symKey` field. The SDK consumed a different key than the app parser
had validated. Double-encoded values also lost a layer of intended data encoding.
The serializer concatenated query values without escaping, and its scheme
conversion replaced every `wc:` occurrence, including text inside a query value.

A bounded synthetic reproduction uses a 64-character `a` topic, a 64-character
`b` key and `relay-data=%26symKey%3D` followed by 64 `c` characters. The real app
parser accepts this as one relay-data value. Before the repair the real SDK
selects the `c` key. No real topic, wallet, relay or credential is involved.

An attacker must control the pairing URI. They already choose a key for such a
URI, so this result **does not demonstrate a new ability to sign, approve a
session, decrypt an existing session, or steal funds**. The demonstrated defect
is disagreement across a validation boundary and incorrect URI round trips.
No end-to-end peer or device exploit is claimed; low severity reflects that scope.

## Repair and compatibility

A fully encoded URI is decoded once only when its scheme is not already `wc:`.
Field decoding is delegated to `URLComponents`; duplicates are rejected after
name decoding. Serialization uses `URLQueryItem`, and scheme conversion changes
only the prefix. Plain and hierarchical URIs, whole-URI encoding, method lists
and legacy missing-expiry behavior remain covered. No wallet persistence,
cryptographic algorithm or transaction format changes.
