# OW-2026-013 — Polygon payouts stay pending when address capitalization differs

Severity: **informational / reliability**. The swap-progress decoder rejected an
observed Polygon payout when its destination had a different capitalization from
the equivalent address in the original memo. This produces a false pending
status, not a wrong recipient, signing bypass or demonstrated fund loss.

## Root cause and reachable display path

Regression-only baseline: `8fa6ee3bf99caf78ab71997b5642e323cccb95da`.
`Packages/OathAnkr/Sources/OathAnkr/ThorchainSwapProgress.swift:64–66` maintains a
second EVM-chain list for comparing destination addresses. It includes ETH, BSC,
AVAX and BASE, but omits POL even though `ThorchainSwapAsset.evmChains` and the
memo parser support Polygon. Matching therefore uses a case-sensitive string
comparison for POL, unlike the other configured EVM chains.

EIP-55 casing encodes checksum information for the same 20-byte address; it does
not select a different account. The test uses the public checksum example from
[ERC-55](https://eips.ethereum.org/EIPS/eip-55) and its lowercase representation.
The app's own EVM network catalog maps Polygon to chain 137. This review does
not assert that a particular live THORChain pool or chain is currently active.

The traced path is Activity transaction details → `ThorchainClient.swapProgress`
→ production progress decoder → `OathWCThorchainProgress`. The view uses
`outboundHash` for the completed delivery stage and `isFinished` to stop polling.
A rejected equivalent address leaves those values incomplete. This path was
source-reviewed; no real provider transaction or iOS screen was executed.

## Fix and identical before/after reproduction

Fix `8dcc9c4c50eae2010b648782c0582c3db70c6357` uses the existing canonical
`ThorchainSwapAsset.evmChains.values` rather than a second incomplete list. EVM
comparisons ignore casing; all other chains retain exact comparison. Amount,
asset, chain, outbound memo, inbound hash and completion-stage checks stay intact.
No signing, broadcast, persistence, migration or authorization behavior changes.

`ThorchainSwapDestinationTests.swift` passes synthetic provider observations into
the production decoder. Polygon native and token payouts each test checksum →
lowercase and lowercase → checksum. The other four EVM chains retain their
previous behavior. Controls reject a different address, chain, asset or inbound
transaction ID on all five chains; TRON's Base58 comparison remains case-sensitive.

Each of the three test methods runs in three fresh network-denied host processes.
Before: **three failed Polygon test executions, with four exact assertion failures
each (12 total), plus six passing control executions**. After: **all nine
executions pass**. The test file hash matches between phases and the compiled
binary hash differs. The runner rejects missing tests, skips, crashes and failures
other than the four expected destination mismatches.
