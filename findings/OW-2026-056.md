# OW-2026-056 · Address checksumming silently accepts malformed address inputs

Severity is low in the current application scope. The public vendored EIP55 helper reproduces the behavior through direct host calls. Its only production call found in this tree is in the bundled ENSResolver; no Oath application call into that resolver was found. An exploitable payment or authentication path is unproven.

The text overload removes every lowercase `0x` substring and passes the result into a permissive hex conversion. Wrong lengths, invalid hex nibbles and non-ASCII input can become a different byte string. The Data overload also accepts arbitrary lengths. Its zip with the hash silently truncates when the hash is shorter than the address text. [Original source](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/Vendor/Reown/Sources/WalletConnectSigner/Ethereum/EIP55/EIP55.swift#L12-L39).

Checksum encoding should accept one 20-byte address. The repair accepts exactly forty ASCII hex digits, optionally preceded by one `0x` or `0X`, checks the raw address and hash lengths, and throws on malformed input. Both public overloads now require `try`; ENS propagates the failure. Valid String output retains its `0x` prefix, and valid Data output retains the previous unprefixed form.

Nine test methods cover 24 known-answer vectors, canonical hash input, sliced Data, malformed sizes, invalid nibbles, embedded/repeated prefixes, Unicode/whitespace and invalid hash lengths. The original implementation fails seven methods with 65 assertions; two positive controls pass. The repaired implementation passes all nine. The fixture injects independent ethers-generated hash values and tests production checksum formatting. It does not test Oath's live crypto provider or establish whole-application reachability.
