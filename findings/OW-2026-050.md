# OW-2026-050 · Invalid persisted Bitcoin indices could terminate three wallet operations

Three independent build 103 host processes terminated while reading deliberately damaged SQLite address rows. Receive and change added one to the largest signed integer before validating it. The branch-state reader requested a UInt32 directly from a wider SQLite integer. GRDB terminated when that conversion failed. The test used a copied temporary database and public fixture addresses. No provider or unauthenticated path to write these invalid rows was established. Severity is low and the demonstrated impact is local availability.

[Build 103 receive and state code](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/Packages/OathDatabase/Sources/OathDatabase/BitcoinLedger.swift#L75-L116) · [Change code](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/Packages/OathDatabase/Sources/OathDatabase/BitcoinSend.swift#L12-L32) · [Original crash frames and repair results](../evidence/5.0.1-build103/bitcoin-indices/focused.json).

[Wallet PR 62](https://github.com/devdasx/oath-wallet/pull/62) checks the signed index before arithmetic and converts the database maximum exactly before returning branch-state metadata. Each operation now returns a typed error for its respective fixture. The repair does not remap or delete a stored address.
