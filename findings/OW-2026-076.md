# OW-2026-076 — Missing Solana nonce value is treated as expiry evidence

Severity: **Low, provider-response validation and pending-transaction reliability.**
Status: **Fixed and retested in public source. Hosted replay pending.**

Baseline: `193912d31c602cce314f540b2bafb64f8606bfbd`, public 5.0.3 (105).
Repair: `6a8bfcfcf6aeabdd858c9f3316ff4bdaeaf245a1`.
Merged in [PR #105](https://github.com/OathWallet/oath-wallet/pull/105), commit
`658245d197592c89c071a946fda0baf8bf93fb41`.

`walletConnectTransactionValid` reads a nonce account using `getAccountInfo`.
It validates the response slot but then uses `SolanaJSON`'s convenience
subscript, which returns `.null` for a missing member. A response with a valid
context but no `value` therefore returns `false`, exactly like an explicit
`"value": null` response indicating account absence.

The pending recovery caller uses a false validity result as one condition for
expiring an older unknown submission after a failed resubmission and another
unknown signature-status read. The database then treats `expired` as terminal
and excludes that record from pending recovery. The initial review path also
misclassifies the incomplete response as an expired transaction. The tests
execute the production client; the full recovery service and database
consequence are source-traced, not executed as an end-to-end app scenario.

Expected behavior: distinguish an explicitly absent account from an incomplete
RPC response. Missing values must throw `.malformed`; an explicit null with a
valid, sufficiently recent context must continue to return false. Valid current
nonce state remains true. Invalid types and stale contexts remain errors.

The repair reuses the existing `SolanaSendClient.value(_:slot:)` validator at
the durable-nonce account read. It changes neither persisted records nor
transaction bytes, signatures, supported formats, RPC endpoints or retry rules.
No user-visible string or migration is needed.

The six-method fixture exercises legacy and version-zero public SDK nonce
vectors through an injected RPC transport. Four controls pass before repair;
the missing-value validity and review methods fail with the expected assertions.
The same fixture passes after repair, alongside 52 adjacent methods: **58 passed,
0 skipped, 0 failed**. Both builds are fresh and each test process denies network
access. Generic unsigned iOS Release compilation passed at the repair and merge
commits. Exact results, source lines,
logs and remaining scope are recorded in the [review](../review/SOLANA-NONCE-VALUE.md).

This does not demonstrate attacker control of an app-configured provider,
unauthorized signing, funds loss or a mainnet exploit. A dishonest provider can
still fabricate a schema-valid response; this repair is not independent state
verification. The whole-wallet review remains incomplete.
