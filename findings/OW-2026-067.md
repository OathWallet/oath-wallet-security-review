# OW-2026-067 — Delayed TRON/TON inventories falsely complete balance refresh

Status: **Fixed in public source and retested locally; hosted replay pending.**

Severity: **Low, balance freshness and retry completion.** No unauthorized
transaction, key disclosure or fund loss is demonstrated.

## Cause

At `fd06fdff104d128e00cc414d2de1472f11752e04`, the production clients stamp
`TronInventory.observedAt` and `TonInventory.observedAt` when the response work
finishes. A request that selected pre-send state can therefore receive a
post-confirmation timestamp when its response arrives late. Both balance-current
predicates accept it. TRON additionally compares only the chain timestamp,
which can precede local confirmation, instead of also requiring the local
send observation time.

Affected source: `Packages/OathAnkr/Sources/OathAnkr/TronClient.swift:212–279`,
`Packages/OathAnkr/Sources/OathAnkr/TonClient.swift:184–223`, and
`Packages/OathDatabase/Sources/OathDatabase/TronSend.swift:25–34`.
`OathAtmosphere/Send/OathPostSendBalanceRefresh.swift` calls these predicates
before returning accepted IDs to the durable refresh worker. The synchronizers
coalesce concurrent refresh callers onto an existing request. This caller path
is source-traced; the fixture does not execute the entire application worker.

## Reproduction

A synthetic transport selects an old native balance and holds its response.
The test installs a final send journal record, then releases the response and
uses the real provider decoder, inventory commit and balance-current predicate.
The old response is incorrectly accepted on each chain. A separate TRON test
uses an inventory timestamp between the chain timestamp and local finality.
Two controls start their reads after local finality and remain accepted.

Final journal records are installed directly: this fixture does not exercise
signing or receipt settlement. All five test processes deny networking. The same
fixture is used before and after; no funded accounts or production requests
are involved. Earlier fixture compilation errors are retained as harness
attempts, not application findings.

## Repair

Commit `63e0be4a10106fc577792a7fb3c6d69b1cc8870c` captures the observation time
before launching the inventory reads. TRON also requires that observation to
be at or after `send.updatedAt`. Old in-flight responses keep refresh pending;
new successful reads remain accepted. No schema migration, stored identity,
signed bytes or transaction outcome changes.

[Reproduction, results and remaining scope](../review/INVENTORY-FLIGHT-TIME.md)
and [hashed evidence](../evidence/5.0.2-build104/inventory-flight-time/manifest.json)
record the exact verification reached. Server caching, block-height proof,
clock rollback, full app integration and other chain predicates remain outside
this repair. This does not establish whole-wallet completion or App Store delivery.
