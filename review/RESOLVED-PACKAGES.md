# What the unsigned iOS build resolved

The app's Xcode lockfile has 12 source-control pins. SwiftDraw already has a dedicated ledger. The [other eleven package trees](../scope/upstream-xcode-packages.json) now have a file-level work queue. It records the exact revision, Git object ID, mode and SHA-256 of each of 5,690 blobs. Two additional rows record nested Git commits, one for a GRDB SQLite checkout and one in yttrium's test scripts. Their contents still need separate scope decisions. The inventory includes build tools, fixtures and examples. Being resolved does not prove a particular function ships in the app. The checksum check reads Git objects and rejects tracked changes to the checkouts.

## Where BitcoinDevKit comes from

OathBitcoin imports BitcoinDevKit in the send signer, PSBT, multisignature and derivation paths. The build log lists the BitcoinDevKit product as a dependency. The [3.1.1 manifest](https://github.com/bitcoindevkit/bdk-swift/blob/55284dc4e767c301c7926c412daad241c0667106/Package.swift) combines generated Swift bindings and a binary target. The repository publishes an XCFramework with libraries for iOS arm64, simulator and macOS. It does not contain the implementation of the Rust library.

At that revision the publication workflow accepts a bdk-ffi tag from the person dispatching it. It checks out that revision, builds the XCFramework, computes its checksum, and commits a generated Swift file and updated manifest in the distribution repo. Its action references use version tags. This describes what the workflow directs; the manifest alone does not identify the precise materials, environment or invocation that built a particular asset. The [actual September 30 release run](https://github.com/bitcoindevkit/bdk-swift/actions/runs/36735728184) recorded v3.1.1 at `1c5f4863c6a53cc9d063d34c4e13c91fea5c58de`, its output checksum, and the distribution commit 55284dc. The bridge manifest pins bdk_wallet 3.1.0 and UniFFI 0.31.2. Its shell script uses locked Cargo resolution, the release-smaller profile and an iOS deployment floor of 15. The Rust profile aborts on panic. [Build log excerpts](../evidence/artwork-host/oath-artwork-host-evidence/upstream/bdk-release-input.json). The repository README, top-level dual-license notice and ignore rules were read alongside that workflow and manifest. The Swift binding internals and Rust implementation remain outstanding.

The [released ZIP](https://github.com/bitcoindevkit/bdk-swift/releases/tag/3.1.1) is 193,934,852 bytes. We independently computed SHA-256 from the cached distribution archive and compared it with the **5e7f8ac46306f9de7ec2cc1c6486d9db5141c793d33cc13071ea7d1e3dae817f** manifest pin. Every regular file in the extracted framework used by the local Release build matched its corresponding archive member, including all three static libraries, all headers, module maps and Info.plist. The verification rejects any extra file, missing entry or mismatched bytes. [Recorded hashes](../evidence/artwork-host/oath-artwork-host-evidence/upstream/bdk-distribution.json). A reproducible Rust-to-archive build and any link to Apple's distributed executable remain open.

SwiftImageReadWrite and swift-qrcode-generator each declare one library and a separate test target, with no external package dependencies in the reviewed manifests. SwiftImageReadWrite puts its image fixtures in the test target. These packaging facts do not decide whether their image codecs or QR generation algorithms handle adversarial inputs correctly.

## Inside the BDK Rust bridge

The bridge [file ledger](../scope/upstream-bdk-ffi.json) records 113 files and 182 Cargo lock entries at the publisher's recorded source. The lock includes tools and tests. It does not show which Rust functions were linked. The reviewed bridge module list separates production modules from the test-only module. The signer container builds a signer map from one descriptor and can take the signing context from a second descriptor. Construction delegates to bdk_wallet; the wrapper exposes entry count and emptiness and performs no independent check of caller intent. The wrapper macros convert values between the bridge and Rust types. Their hash constructors delegate to deserialization or hex parsing, and the string error retains the rejected input. Logging that error and the caller's handling of mismatched descriptors still need review. The UniFFI settings select generated module names and its entry point invokes the upstream binding generator. The Rust toolchain file selects 1.90.0.

The eight current bridge dispositions cover these small adapters, the two configuration manifests and Apple packaging. PSBT parsing, the upstream wallet and signer implementation, exported Swift bindings, crate builds and their runtime behavior remain separate work.

## Reproduction

Run the generic Release build with `python3 scripts/run.py .work/source build --scratch .work/release-build --output .work/checks`. Then run the resolved package inventory and archive comparison shown in the [release-build workflow job](../.github/workflows/review.yml). They read already resolved files on disk. Only downloading the official archive requires network access. Each manual disposition in the new ledger is bound to the SHA-256 of its reviewed file.
