# Curve tables in the 5.0.1 package resolution

> Current audit target: [5.0.2 (104) prerelease](RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

The resolved Swift secp256k1 package embeds three upstream source trees. We compared every tracked path, Git object and mode under each vendor directory to a separate public checkout. All 177 Bitcoin Core secp256k1 entries, 238 Blockstream secp256k1-zkp entries and 1,043 Apple Swift Crypto entries matched. The Bitcoin Core reference in the package metadata identifies an annotated tag object. It resolves to commit `1a53f4961f337b4d166c25fce72ef0dc88806618`. Comparing those two identities directly would give a false mismatch.

We compiled the upstream table generators for both curve repositories. Both tables regenerated byte for byte in each vendor tree and in the corresponding Swift package source directory. Separately, a Python implementation used affine addition and integer arithmetic to compute each expected coordinate. It checked all 16,384 odd multiples of the two bases and all 1,760 points across the three signed-comb configurations. The eight verified source paths contain two distinct tables. The source comparison does not establish constant-time operation or the correctness of signing, or turn the rest of either dependency into reviewed source.

The [compiler manifest](../evidence/5.0.1-build103/compiler/release-inputs.json) identifies direct inputs to the actual unsigned build of the release tag. It covers 2,357 distinct source and header inputs. Prebuilt libraries, runtime-loaded data and implementation-level reachability require separate checks. [Tree comparisons and table digests](../evidence/5.0.1-build103/secp-tables/result.json) · [Compiled-input dispositions](../evidence/5.0.1-build103/compiler/dispositions.json).

To reproduce, check out the package and the three named upstream revisions recorded in the JSON result. Fetch the Bitcoin Core annotated tag object as well. Run the following with a C compiler, Git and Python 3.11 or later:

```sh
python3 scripts/secp-table-provenance.py /path/to/swift-secp256k1 /path/to/secp256k1 \
  /path/to/secp256k1-zkp /path/to/swift-crypto /tmp/secp-table-results.json
```

The [Actions recipe](../.github/workflows/secp-tables.yml) supplies the exact fetch commands. The comparison of vendored source is separate from the two independent ways the tables were checked.
