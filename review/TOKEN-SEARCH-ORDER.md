# Token-search refresh ordering: fixture repair

The exact build 103 GitHub host run failed `testOldRefreshCannotReplaceNewWalletNetworkResults`: its first assertion saw an empty result list instead of Ethereum. The later wallet-switch assertion did not fail. The original report and log remain in the final [baseline CI snapshot](../evidence/5.0.1-build103/ci-artifacts-checkpoint9.json), including its failed status. This is a confirmed test synchronization defect, not a confirmed wallet vulnerability.

The original fixture waited 200 milliseconds after starting a task. Production search first debounces for 150 milliseconds, then awaits catalog lookup and detached mapping before publishing cached results. There is no contract that this work finishes in the remaining 50 milliseconds. Increasing the sleep would only change the race. The source already checks its request generation after each asynchronous publication boundary.

The replacement fixture holds the first refresh with a continuation and signals only after cached results are published. The test waits for that signal, completes a second wallet's search, then releases the old response. It checks both the visible Tron results and that the old generation did not issue another catalog read. It runs with immediate and deliberately delayed catalog reads. A separate test resets the model while refresh is suspended and verifies that late completion cannot repopulate results. The former 10-millisecond reset sleep is removed from the name-search test; its deterministic coverage lives in the new reset case. Ten-second expectation deadlines detect a broken test; they do not choose the interleaving.

The app implementation is byte-identical to baseline. Only the public host fixture and its command-line harness change in `b57d05196be319d1f0530e28f667eb89023a1c4a`. The harness accepts a named test filter and isolated scratch directory; no live mode is enabled. [Test source](https://github.com/devdasx/oath-wallet/blob/b57d05196be319d1f0530e28f667eb89023a1c4a/Tools/TokenLookupValidation/TokenLookupTests.swift) · [Production model](https://github.com/devdasx/oath-wallet/blob/c7acd23bb139864a40273f405d18b479589d2b20/OathAtmosphere/Tokens/OathTokenSearchModel.swift).

The complete 257-line model was read. Review covers wallet-scoped request construction, matching constraints, debounce/cancellation checks, generation-checked publication, bounded RPC fan-out and the selection queue's capacity, identity coalescing and completion checks. The supplied persistence callback, provider implementations, callers' navigation/lifetime behavior and UI rendering are separate boundaries. The file is therefore recorded as partially reviewed; passing this fixture does not close those integration concerns.

The reproducible [audit replay](../scripts/token-search-order.py) compares the production implementation with a temporary mutant that removes exactly the two refresh generation checks. The mutant is never committed to the application. Each selected test runs in a network-denied host process, and its exact assertion count and completion are checked. Both production cases pass. Removing the two guards produces exactly four failed assertions in the wallet-switch case and two in the reset case. All four network-denied executions are verified. [Replay receipts](../evidence/5.0.1-build103/token-search-order/result.json). The complete host suite passes 20 tests and skips four optional live checks. Publication validation is recorded separately from these cases.
