# Wallet identity and display-number review on build 103

The private-key identity model stores key bytes separately from network scope and compressed or extended-key metadata. We read the complete model in the exact release. Its structure check rejects duplicate or empty network sets, limits uncompressed encodings to the supported Bitcoin-family chains, bounds each extended string and confines it to the corresponding network. The independent import boundary also checks scalar validity. A structurally plausible value by itself does not prove a valid credential. Identity comparisons preserve the historical full-EVM scope and the compressed default. When extended strings differ, the model compares recovered branches for the appropriate network and rejects decoding failures. The wallet tests included the 56-case UTXO identity corpus, the synthetic import-format overlap and known Bitcoin receiving addresses. The manual file disposition covers this model. The upstream derivation implementations retain their own dispositions.

For the recovery draft we traced input replacement, explicit format choice, submission and clearing. Rejected or composing input yields no eligible formats. The request ID formerly belonged to the switcher and rotated for text edits, so changing only the selected format could reuse an earlier request. [OW-2026-046](../findings/OW-2026-046.md) covers both the draft and vault commit paths. QR scanner implementation and UI rendering remain separate review areas.

We also traced the authenticated envelope's family reconciliation, both derived-wallet allocation paths and the SQL transaction which assigns default labels and sort positions. The envelope crash reproduced before the SQLite step. The independent SQLite crash tests reached different production lines and each used a fresh process. [Encrypted vault](../findings/OW-2026-047.md) · [Database writer](../findings/OW-2026-048.md). These are partial dispositions for the larger envelope, actor and database files.

The Arc review followed the optional token-label boundary, mandatory scale parsing, tracked-holding fallback and the diagnostic attached to an invalid transaction sender.
