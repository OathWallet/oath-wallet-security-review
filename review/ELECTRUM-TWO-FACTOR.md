# Electrum two-factor recovery and cosigner identity

Electrum’s original two-factor wallets use the first twelve words for one cosigner and the remaining words for a second. Later twelve-word two-factor seeds use separate hardened branches. The upstream TrustedCoin implementation selects the scheme from the original words. Normalizing the entire phrase first can remove spaces between Chinese, Japanese or Korean characters, changing which scheme is selected. Oath’s earlier recovery screen also passed the compacted phrase to the wallet engine. In the encrypted-vault test this returned an invalid-phrase error.

The synthetic 24-word fixture failed four cosigner assertions with ordinary and ideographic spaces. With the correction, the same byte-identical test passes. The app now retains significant boundaries for recovery, and independently normalizes the KDF input for each legacy cosigner. The first receive addresses of two synthetic fixtures were compared against an offline Go implementation using btcsuite. The oracle also reproduced previously published English fixtures for both two-factor schemes. The integration suite passed 205 assertions at the repair branch, including recovery from a freshly opened encrypted vault. ## Findings in the validation tools

Two earlier package assertions had missed detached diagnostics after sleeping for 100 milliseconds. The retests wait for the matching error in its originating operation. A separate TRON fake transport retained only one pending history request. If two reads overlapped, the earlier continuation was lost. A deterministic two-request test failed before the fixture repair and passed afterward. In the refresh harness, a suite selector previously matched no tests and still returned success. The runner now requires real named cases to pass. The restored test covers reuse of an in-flight refresh and late completion after replacement. [Test repairs](https://github.com/devdasx/oath-wallet/pull/52).

These host results concern deterministic synthetic inputs. They do not establish how many users had a matching two-factor wallet. The preceding report retains its original source and outcomes. The verifier read that metadata from the exact manifest-pinned archives, checked that both cached device binaries matched the archive members byte-for-byte, and compared the app’s embedded executable sections with them.
