# Bitcoin connection requests and partially signed transactions

> Current audit target: [5.0.2 (104) prerelease](RELEASE-5.0.2-104.md). Earlier results below retain their original tested versions and commits; they are not retroactively tests of build 104.

The public BitcoinConnectRequest initializer reads a bounded peer payload, checks the selected method and chain identifier, binds the account, and validates parameters for the selected method. When a saved request returns through Codable, validate() encodes and runs the initializer again, then checks equality. Address parsing uses the selected Bitcoin network. A testnet-formatted address can be mapped to a corresponding owned mainnet script when matching the negotiated account. The connection does not get a new signing key from that change of address encoding.

The PSBT reader first passes the bounded decoded container to BDK, then reads its key-value maps. It rejects duplicate keys within a map, non-minimal CompactSize encodings and inconsistent map counts. For review, each input's previous transaction is hashed and matched to its outpoint. A supplied witness output must also match the amount and script of that parent. Input and output totals are checked against Bitcoin's supply bound before addition. Requested input indices must be unique, owned and associated with the requested address. The selected sighash is restricted to ALL or Taproot DEFAULT. Previously finalized inputs and Taproot script-leaf signing are rejected on the reviewed path.

The signing entry point enforces the plan lifetime and rebuilds the review. For a signPsbt request it compares the reviewed unsigned transaction and selected input list to the original request. For a transfer it checks the recipient, amount, owned change and optional OP_RETURN memo. For each authorized input it derives a descriptor and verifies the resulting script. It scopes the BDK signing operation to that input and copies back only its signed map. It checks the fee again before optionally extracting a transaction. The app entry point also checks that the account belongs to the selected wallet and that the plan's recorded request equals the request being approved.

Twelve [existing host cases](../evidence/artwork-host/oath-fee-final-evidence/psbt/selected-checks.json) passed as part of the Bitcoin package suite. They include wrong-network requests, mismatched parent and sighash information, modified plans, wrong keys, recipient/change validation and preservation of unselected inputs. This is a subset of the package totals.

Outstanding work includes the maximum aggregate memory used when many inputs reference large parents, the trust boundary for persisted ownership metadata, independent consensus verification of each signature format, and runtime dApp-to-user approval behavior. A malformed input or an unproven resource bound alone does not establish a finding here. The source dispositions cover the request decoder and the PSBT paths listed above; the PSBT review remains partial.

## Packet and parent limits at progress 47

[OW-2026-032](../findings/OW-2026-032.md) confirms the earlier shared-parent concern. The fixed source enforces the packet limit while constructing the review. The fetch test archives the same URLProtocol fixture with both source revisions. Its intercepted responses carry six distinct hash-verified synthetic funding transactions, each under 100 kB. The original collector returned all six despite their combined size. Two-parent batches returned the two expected byte sequences. The final check set also exercises shared parents, exact wire overhead and a smaller revalidatable plan. Peak URLSession memory and iOS runtime behavior are still unmeasured.
