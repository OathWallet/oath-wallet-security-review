# Wallet Core derivation path C interface

Upstream commit `d40d24a63d92619167903369308bf0e2f7eb3a59` (4.8.4).
Read the two public path/index headers and their two C++ wrapper implementations, including constructors, getters, ownership, string conversion and deletion. Reconciled them with the underlying DerivationPath parser and its short-path defaults. The numeric path constructor sets the first three components hardened and the last two unhardened; the text constructor catches parser exceptions and returns null. Index lookup checks the requested offset before copying the child into a new allocation. Deleting the parent leaves the returned child usable. Returned description strings have independent ownership.

The sanitized fixture compiles the production C API, parser and string interface. It compares 512 deterministic five-part numeric paths with independently formatted descriptions and parsed values, including child 0 and 2147483647. It checks out-of-range index lookups, separately owned child lifetimes, hardened index descriptions, and rejection of seven malformed strings including an embedded NUL. Two compatibility cases cover root defaults and normalization of a relative path with a trailing slash.

A boundary remains: the numeric API accepts a uint32 with the high child bit already set. The same component expressed in decimal text is rejected. The fixture records this asymmetry. An application caller should not treat successful numeric construction as child-index validation. The headers have reviewed dispositions. The wrapper implementations remain partial while the numeric-domain and caller-reachability questions are open. The reviewed OathAtmosphere sources have no direct construction call to this path/index API. This probe does not establish an exploitable signing or restoration path. Other SDK consumers, callers with invalid pointers, resource exhaustion and cryptographic key derivation itself are outside this wrapper test. The general-purpose string byte accessor and mnemonic C-string conversions retain separate review questions.

Run `sh scripts/core-path-boundary.sh <clean-wallet-core-checkout>` with Clang and Ruby. It generates the required TWHRP header with upstream's registry generator in a temporary directory. The first exploratory compile lacked this generated header and failed before running tests. Its log is retained separately. The completed host run uses AddressSanitizer and UndefinedBehaviorSanitizer. It exercises upstream source, not a distributed Apple binary.
