# Build 103 custody and handoff source checks

The source revision for this review is `c7acd23bb139864a40273f405d18b479589d2b20`. File coverage in this note applies to that tag. Post-release changes have their own evidence.

- The aezeed Swift bridge bounds input and password byte lengths, requires 24 words in the bundled 2,048-word dictionary, and checks the CRC before calling the native decoder. Recognition only means the envelope can be parsed. The decoder validates the version and authenticated native result. Transient arrays are cleared on exit; the returned material necessarily retains its entropy and password. The changed dictionary loader records only fixed internal resource-error reasons. Seven package tests passed.
- The diagnostics exclusion policy compares structured source locations, operations, provider domains, codes and context. The new history rule is limited to one specific recovery probe and five chains. We read it with the existing rate-feed, Aptos, fatal-event and bundled-rule guards. The rule changes local outbox eligibility. They neither accept a transaction nor change retry results. The full diagnostics suite on the tag passed 119 tests and skipped two.
- The handoff envelope carries a UUID reference in the URL. Its parser limits the length, scheme, host, path and allowed arguments. On consumption the mailbox takes a bounded entry, checks identity, format version and a five-minute expiration window, then validates payload type and account scope. The reference and format do not authenticate ownership of a wallet; the app’s import adapter verifies derived addresses. Twelve package tests passed using in-memory storage. The package manifest has no external dependencies.
- The Keychain implementation selects an explicit access group, disables synchronization, and requires an unlocked device for new items. A consume operation returns bytes only after successfully deleting the matching UUID. Publishing deletes old entries before adding a new one. Simultaneous publication through independent mailboxes and behavior across production access-group entitlements remain open. The in-memory tests cannot prove those guarantees.
- The import adapter accepts only supported chain mappings, rejects duplicate normalized network/account pairs, preserves the private-key network scope and rejects an extended-key declaration that lacks its chain code. Electrum and aezeed require a single validated Bitcoin address and derivation path. BIP39 and private-key imports pass through the normal restore validator and must match the declared public addresses. The two new backup-offer assignments describe the type of reminder. They grant no new access to secret material. Full cross-format and platform handoff coverage remains open.
- The batch-backup helper deduplicates wallet IDs, performs one password-derivation operation at a time, reports per-wallet results and propagates cancellation. Its result callback reports the preparation operation; cloud confirmation is a distinct operation. We traced the account and generation checks around cloud read/write, same-file byte comparison, coordinated and bounded reads, filename validation and metadata discovery. A real iCloud account change mid-operation, independent filesystem writers and races between file inspection and opening remain outside this run.
- The changed URL type names use the bundle identifier setting. All three names expanded correctly in the generated Release Info.plist and their scheme arrays matched the source. The built product has the fetch background mode and no App Transport Security exception. It registers neither the handoff URL scheme nor the configuration key required by the default handoff mailbox. The package behavior above therefore does not prove that an external caller can enter this flow in the released configuration. The provenance file distinguishes reviewed binary input from the separate packaging repair of four protobuf Info.plists and identifies device symbols. Build 103 uses the eight-repair framework. The subsequent Swift path artifact and app integration are tracked separately.
