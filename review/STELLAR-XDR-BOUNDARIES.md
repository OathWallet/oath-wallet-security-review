# Stellar contract-call envelope decoding

The public WalletConnect initializer parses a peer's XDR before presenting the transaction. This subreview follows the binary path into the pinned Soneso Swift SDK at `b5dac0a6e8ff312d597c9a3b4269b03131d66e0d`. The source pin, compiler-input trace and adversarial tests are distinct evidence.

Start with the outer transaction discriminator. A v1 transaction has a source, fee, sequence, preconditions, memo and an operation vector. The fixture has one invoke-host-function operation and a one-character contract function name. One argument is a Soroban vector containing another vector. This is enough structure to exercise two different boundaries.

1. **Declared element count.** The generated InvokeContractArgs decoder delegates to the SDK's generic array decoder. It reads an unsigned count, checks the schema ceiling and checks the remaining bytes at a minimum four bytes per element before reserving capacity. The fixture replaces one element with a claim of 4,294,967,295 elements and checks for the remaining-bytes error. This checks one allocation path. It does not measure peak allocations for all schema types.
2. **Recursive values.** In the vec branch, SCVal decodes an optional-presence flag, then a nested array of SCVal. The generic XDRDecoder increments a per-decoder counter when entering binary-decodable values and restores it on unwind. The fixture requests 512 nested vectors in a small packet and requires the specific depth error while traversing them.
3. **Canonical representation.** A nonzero optional flag can be interpreted as present by the SDK. Oath re-encodes the envelope and compares the full byte sequence. Replacing a canonical 1 with 2 or appending an otherwise harmless word should fail this equality check. These tests require Oath's malformed response rather than accepting an arbitrary thrown error.
4. **Valid control.** The two-level vector goes through Oath's request, review, sign and verify paths using a fixed synthetic signing seed. The hash is independently generated with OpenSSL's Ed25519 public key derivation, a hand-written wire layout and Python SHA-256. The [vector](../fixtures/stellar/nested-testnet-vector.json) uses the testnet signature domain and requires no service or funded address.

The [fixture](../fixtures/stellar/StellarEnvelopeLimitTests.swift) and [runner](../scripts/stellar-envelope-limits.py) are versioned. The seven dependency files marked partial cover these specific binary decoding paths. The SDK's text converters, other operation families, version-zero and fee-bump conversion, XDR encoding in general, ledger acceptance and the remainder of the parser remain open. The deliberately minimal contract call has no network simulation or ledger execution evidence.

All five cases passed on public app commit `0e50b16ae1ced7934d57dba42d3e6e69ccf6cfc8`. [Per-case results and fixture digest](../evidence/provider-response/oath49-http-evidence/stellar/stellar-envelope-limits.json).
