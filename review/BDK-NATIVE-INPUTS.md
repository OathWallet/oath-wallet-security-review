## Scalar validity, tweaks and the historical DER parser

We read the full `secp256k1-sys 0.10.1` build script. It compiles the curve implementation, two precomputed tables and the historical DER reader. It selects multiplication parameters by feature, enables several curve modules, and conditionally enables recovery. Its compile-error retry can add WebAssembly headers. The actual target compiler’s include lists establish which files this build used. Registry archive identity is `d4387882333d3aa8cb20530a17c69a3752e97837832f34f6dccc760e715001d9`.

We traced scalar validity and point creation through the Rust wrapper into the native implementation. A secret scalar must be nonzero and below the group order. Public-key creation substitutes one internally for an invalid scalar before clearing the return value on failure. Tweak addition separately rejects overflowing tweaks and a zero result; the public operation rejects the corresponding point at infinity. The fixture exercises the production Rust and C implementation on the host and checks expected public points with OpenSSL. It covers 137 inputs including zero, the order, order plus one, modular wraparound, and sums that become zero. The compiled crypto crates had the same feature sets as the device build. Device execution, side-channel properties and all field arithmetic remain separate review areas. [Rust test](../fixtures/bitcoin-native/curve.rs) · [Independent input generator](../scripts/bdk-native-curve.py).

The small historical DER parser was read in full. It bounds the length-of-length before shifting, checks integer lengths against the remaining buffer before copying, strips leading zeroes and never copies more than 32 bytes into either scalar. It intentionally ignores certain noncanonical lengths and trailing bytes. An overflowing scalar can produce a parsed object whose signature is invalid. The API’s parse success must therefore be distinguished from ECDSA verification. The ordinary rust-bitcoin ECDSA signature constructor inspected uses the strict DER API. We have not inferred global unreachability of the lax API from that observation. A known signature, two noncanonical encodings, 70 truncations, oversized lengths, scalar overflow and 2,048 deterministic bounded inputs exercised the actual historical parser. The noncanonical encodings passed historical verification and failed strict parsing as expected.
